# 本地 AI 简历档案库

保持两个业务板块：上传简历、简历库。模型配置为辅助设置，不含招聘流程、面试、员工花名册功能。

## 人事交付版 v1.2

正式首页按人事反馈恢复深蓝侧栏、浅色背景和白色表格，真实调用服务端 API、OCR、模型与 SQLite，不使用示例数组。每份简历只占一条表格记录，搜索匹配摘要位于技能右侧的“匹配内容”列。旧 `/preview/` 地址跳转到首页，无暂停按钮、Workspace 文案和设计版本标记。

人事使用 Windows x64 便携包：完整解压后双击 `启动.cmd`，填写自己的模型配置即可。包内包含 Node.js 24.16.0、依赖与许可证，不需要 npm 安装；`停止.cmd` 可正常关闭服务。完整日常说明见 `使用说明.md`。

源代码打包运行 `node scripts/package.js`。脚本按白名单复制程序及依赖，生成带 SHA-256 清单的 ZIP；不打包 `data/`、`.env`、真实配置、测试简历和日志。Node 官方许可证需先放入工作目录的 `work/NODE-LICENSE.txt`。程序包是 Windows x64 本机交付，不是签名安装器。

要求 Node.js **24.14–24.x**（本次验证 24.16.0），使用内置 `node:sqlite`，不需要安装数据库服务。Express、原生前端、PDF/OCR 库沿用现有项目。

打开 <http://127.0.0.1:3000>。服务仅绑定本机回环地址，不能作为局域网多人服务直接部署。已有服务占用端口时先关闭旧服务，或设置 `PORT`。同一数据目录只允许一个实例。

测试创建独立临时目录，真实 PDF 解析、HTTP 请求和 SQLite 均不做 Mock。普通集成测试不调用外部 AI。`node scripts/verify-live.js` 是显式运行的真实模型冒烟测试：读取当前配置，仅发送脚本内的虚构简历，使用临时数据库，可能产生少量 API 费用。

## 已实现流程

1. 多选或拖入 PDF，每份最多 20MB、30 页；校验扩展名与 PDF 文件头。
2. 先保存原文件与数据库任务，返回排队状态；后端逐份解析，刷新或关闭页面不取消任务。
3. 文字型提取文本；文字不足的页面用本地中英文 OCR，支持混合型 PDF。
4. 配置 API Key 后，调用兼容 Chat Completions 的模型进行结构化提取；否则明确显示“本地规则提取”。模型失败不会静默退回规则并伪装成功。
5. 状态为排队、解析中、已归档、失败。失败保留文件，可单独重试。进程重启后未完成任务重新排队；中断时可能重复产生模型调用费用，但不会新增一条简历记录。
6. 相同 PDF 字节内容按 SHA-256 唯一约束复用原记录；不是候选人同名合并，不增加待核对流程。
7. 简历库默认只搜索关键字段（姓名、任职公司、岗位、技能、学历、学校、专业、联系方式及文件名）；勾选“包含简历全文”才搜索正文。空格分隔词为 AND，支持学历、任职公司筛选和分页。匹配片段及字段中的命中词使用安全 DOM 高亮。
8. 详情显示字段、全文、逐页原始 PDF 图像预览及原始 PDF 链接。预览在本地子进程中渲染，不依赖浏览器 PDF 插件。
9. 模型提取当前与历史任职公司、最高学历学校和专业。历史记录未提取的新字段保持为空，仍可按全文找原信息，不编造回填。

## 模型配置

页面“模型设置”填写 Base URL、API Key、模型名称。默认 Base URL 为 `https://api.deepseek.com`，沿用原先 `deepseek-chat` 模型名称，是否可用以供应商账号为准。Base URL 应为根地址或 `/v1` 根路径，不含 `/chat/completions`。

密钥只在服务端使用，保存后不回显；密钥输入框留空保留原配置。可用 `.env` 设置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，数据库中的非空设置优先。真实 `.env` 不提交。

“测试连接”调用已保存的配置发送一条不含简历资料的测试请求，可能产生少量接口费用；不会将当前输入框中未保存的密钥作为生效配置。

默认只允许 `api.deepseek.com`。更换供应商时，由本机管理员在 `.env` 设置 `LLM_ALLOWED_HOSTS`（逗号分隔）。模型地址要求 HTTPS、443 端口、不含用户密码；每次请求检查 DNS 结果并固定连接到已检查的公网 IPv4，拒绝内网地址和重定向。暂不支持本地 HTTP 模型端点及 IPv6-only 提供方。

OCR 安装好语言包后不联网；AI 提取会将简历文本发送至配置的服务。模型请求超时 60 秒，PDF/OCR 超时 180 秒，不自动无限重试。最多提交 30,000 个字符给模型，全文仍本地保存和检索；超长简历后半部分可能不参与 AI 字段提取。

## 数据与迁移

- `data/library.sqlite` 及 WAL/SHM：结构化字段、任务、设置与迁移版本。
- `data/uploads/`：原始 PDF，不在公开静态资源目录。
- `data/incoming/`：上传临时文件。
- `data/ocr-languages/`：本地语言包缓存。
- `data/runtime.lock`：防止同目录多实例；异常退出后启动会检查旧进程是否仍存活。

首次升级自动将旧 `settings.json`、`resumes.json` 导入 SQLite，一次性导入标记使用事务保存；旧 JSON 和原文件均保留、不覆盖。完全相同的历史 PDF 在新库合并为一条记录，旧记录仍保留在原 JSON。之后新数据只写 SQLite；不要同时运行旧版本继续往 JSON 写入。迁移遇到缺失文件或格式损坏会明确停止，不将错误当空库。

`DATA_DIR` 可指定独立数据目录。备份时先关闭服务，再复制整个数据目录（包括 PDF 和数据库）。恢复时同样先关闭服务，再使用完整备份。当前未增加 UI 删除或一键恢复功能。

密钥以本机服务端设置形式保存，**不是加密保险库**；数据库、备份、旧设置 JSON 可能包含密钥，需由操作系统用户权限保护。目录已排除版本控制。

## 本机安全边界

不新增账号系统。每个浏览器先建立随机本机会话，API 逐请求检查会话 Cookie；写入请求另校验 CSRF Token。Host/Origin 与跨站来源校验防止跨站操作和 DNS rebinding。该会话不区分同一操作系统账户下的人，不适合共享机器、外网或多租户场景。

SQL 值使用参数绑定，状态白名单与唯一约束在服务端落实。原文件与预览只能通过受保护的记录 ID 接口读取。页面动态内容使用 DOM textContent，CSP 禁止内联脚本；API 不返回密钥、存储路径或内部堆栈。

PDF/OCR 使用独立子进程，避免 Windows 原生依赖崩溃牵连 Web 服务；子进程隔离不是恶意文件的完整沙箱，不应向公网开放上传。

## 模块

| 路径 | 职责 |
|---|---|
| `server.js` | 启动、端口和退出处理 |
| `src/app.js` / `routes.js` | 应用装配、接口与上传校验 |
| `src/security.js` | 本机会话、CSRF、Host/Origin、响应头 |
| `src/model-service.js` | 模型配置、网络边界、超时与字段校验 |
| `src/task-service.js` | 持久任务消费与失败重试 |
| `pdf-text.js` / `src/*worker.js` | 复用 PDF/OCR 与独立进程预览 |
| `src/repository.js` / `data-lock.js` | SQLite 查询、事务、历史导入和单实例锁 |
| `src/search.js` | 固定搜索范围、分词与匹配片段 |
| `migrations/` | 版本化数据库结构 |
| `public/js/` | API、统一 DOM/UI 辅助函数及页面模块 |
| `tests/` / `scripts/` | 独立数据测试、检查和显式冒烟测试 |
| `launcher.js` / `启动.cmd` / `停止.cmd` | 便携启动、服务身份识别与正常停止 |

具体验收见 `验收记录.md`。尚未覆盖所有手写、模糊、旋转、复杂双栏扫描件；批量实际识别准确率需要继续用业务样本评估。
